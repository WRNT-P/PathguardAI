# API contract — หน้า admin: ปักหมุดสถานที่ + เขตอันตราย

> เขียน 2026-08-20 · สำหรับคนที่ทำหน้า admin (คนที่ 3)
> **สถานะ: backend เขียนเสร็จและมีเทสต์แล้ว (20 ส.ค.)** — 15 เทสต์ผ่าน
> ยิงจริงได้เลย ไม่ต้อง mock แล้ว
> เปลี่ยนจากฉบับแรกแค่ 2 จุด ทั้งคู่เป็นการ *เพิ่ม* ไม่กระทบของที่เขียนไปแล้ว:
> `created_by` (ไม่บังคับ) ในเขตอันตราย และคำอธิบายเรื่องหมุดที่ AI เรียนรู้เอง
> ถ้าจะเปลี่ยนอะไรในนี้ ต้องบอกกันก่อน อย่าแก้ฝ่ายเดียว

## ทำไมต้องมี 2 ฟอร์มนี้

| ฟอร์ม | ปลดล็อกอะไร | หมายเหตุ |
|---|---|---|
| ปักหมุดสถานที่ | ปัจจัย `unfamiliarity` **10%** ของคะแนนความเสี่ยง | ผูกกับผู้ป่วยรายคน |
| เขตอันตราย | ปัจจัย `danger_zone` **15%** | **ไม่ผูกกับผู้ป่วย** เป็นเขตของพื้นที่ ใช้ร่วมกันทุกคน |

เขตอันตรายคือปัจจัยเดียวที่ทำงานเต็มร้อยตั้งแต่วันแรก ไม่ต้องรอระบบเรียนรู้อะไรเลย
แต่ตอนนี้ตารางว่าง = 15% นั้นเป็น 0 อยู่

# 1. หมุดสถานที่

## `POST /api/patients/{patient_id}/places`

บันทึกหมุด **ทั้งชุด** ของผู้ป่วย 1 คน

> ⚠️ **ส่งมาทั้งชุดทุกครั้ง ไม่ใช่ทีละหมุด** — ของเดิมถูกทับทั้งก้อน
> เพราะ backend ต้องเห็นทุกหมุดพร้อมกันถึงจะแจก `cluster_id` เรียงต่อเนื่องได้ถูก
> เพิ่มหมุดที่ 4 = ส่งหมุด 1,2,3,4 มาใหม่ทั้งหมด

### Request

```json
{
  "places": [
    {
      "place_name": "บ้าน",
      "latitude": 13.7563,
      "longitude": 100.5018,
      "visit_rank": "daily_live",
      "stay_rank": "all_day",
      "radius_m": 150
    },
    {
      "place_name": "รพ.สต.",
      "latitude": 13.7601,
      "longitude": 100.5077,
      "visit_rank": "weekly",
      "stay_rank": "about_hour",
      "radius_m": 400
    }
  ]
}
```

| ฟิลด์ | ชนิด | บังคับ | มาจากช่องไหนในฟอร์ม |
|---|---|---|---|
| `place_name` | string | ✅ | ชื่อสถานที่ |
| `latitude` | float −90..90 | ✅ | หมุดบนแผนที่ |
| `longitude` | float −180..180 | ✅ | หมุดบนแผนที่ |
| `visit_rank` | enum ข้างล่าง | ✅ | dropdown "ไปบ่อยแค่ไหน" |
| `stay_rank` | enum ข้างล่าง | ✅ | dropdown "อยู่นานแค่ไหน" |
| `radius_m` | int 20–5000 | ❌ (default 150) | dropdown "ขนาดพื้นที่" |

### enum ที่ใช้ได้

**`visit_rank`** — dropdown "ไปบ่อยแค่ไหน"

| ค่าที่ส่ง | ข้อความที่ผู้ดูแลเห็น |
|---|---|
| `daily_live` | อยู่ประจำ / นอนที่นี่ |
| `most_days` | เกือบทุกวัน |
| `weekly` | สัปดาห์ละครั้งสองครั้ง |
| `rare` | นานๆ ครั้ง |

**`stay_rank`** — dropdown "อยู่นานแค่ไหนต่อครั้ง"

| ค่าที่ส่ง | ข้อความที่ผู้ดูแลเห็น |
|---|---|
| `all_day` | ทั้งวัน / ค้างคืน |
| `few_hours` | สองสามชั่วโมง |
| `about_hour` | ราวหนึ่งชั่วโมง |
| `brief` | แป๊บเดียว |

**`radius_m`** — dropdown "ขนาดพื้นที่": บ้านหลังเดียว `150` · ตลาด/วัด `400` · โรงพยาบาลทั้งแห่ง `800`

> ค่านี้**มีผลจริงแล้ว** (แก้ 20 ส.ค.) — เดิมระบบจับคู่สถานที่ด้วยรัศมี 150 ม. ตายตัวทุกหมุด
> ตอนนี้แต่ละหมุดใช้รัศมีของตัวเอง หมุดที่ไม่ส่งค่ามาก็ยังเป็น 150 ม. เหมือนเดิม

> **ส่งชื่อระดับมา ห้ามส่งตัวเลข** — backend แปลงเป็นตัวเลขเอง (`daily_live` → 100 เป็นต้น)
> เหตุผล: ค่านี้ระบบคิดแบบ *เปรียบเทียบกันเอง* (`freq ÷ max(freq)`) ถ้าให้ผู้ดูแลพิมพ์เลข
> แล้วเขาใส่ใกล้ๆ กันทุกหมุด ทุกที่จะกลายเป็น "คุ้นเคย" เท่ากันหมด แล้วระบบจะเลิกเตือน
> แม้ผู้ป่วยไปโผล่ที่ไม่เคยไป — พังแบบเงียบสนิท dropdown บังคับให้ค่าต่างกันเป็นชั้นๆ

### Response `201`

```json
{
  "patient_id": 7,
  "places": [
    {"cluster_id": 0, "place_name": "บ้าน", "latitude": 13.7563, "longitude": 100.5018,
     "visit_rank": "daily_live", "stay_rank": "all_day", "radius_m": 150, "source": "manual"},
    {"cluster_id": 1, "place_name": "รพ.สต.", "latitude": 13.7601, "longitude": 100.5077,
     "visit_rank": "weekly", "stay_rank": "about_hour", "radius_m": 400, "source": "manual"}
  ],
  "count": 2
}
```

- `cluster_id` **backend แจกให้** เรียง 0,1,2… ตามลำดับใน array ที่ส่งมา — UI ไม่ต้องส่ง แต่เก็บไว้แสดงตอนแก้ไข
- `source: "manual"` backend ใส่เอง แยกหมุดที่คนปักออกจากหมุดที่ AI เรียนรู้เอง

## `GET /api/patients/{patient_id}/places`

โหลดกลับมาแสดงตอนเปิดหน้าแก้ไข — คืนรูปเดียวกับ response ข้างบนเป๊ะ
(`visit_rank`/`stay_rank` ถูกเก็บไว้ด้วย จึงเลือก dropdown กลับได้ตรงเดิม)

หมุดที่ AI เรียนรู้เองจะมี `source: "learned"` และ `visit_rank: null`
→ **UI ควรแสดงแบบอ่านอย่างเดียว แก้ไม่ได้** เพราะไม่ได้มาจากการกรอก

การ POST ทับ **ลบเฉพาะหมุดที่คนปัก (`source: "manual"`) หมุดที่ AI เรียนรู้เองไม่หาย**
แล้วแจก `cluster_id` ใหม่ให้ทั้งชุด (หมุดคนก่อน แล้วต่อด้วยหมุด AI) — `cluster_id`
ของหมุดเดิมจึงเปลี่ยนได้ ให้ใช้ค่าที่ได้จาก response เสมอ อย่าจำค่าเก่าไว้

# 2. เขตอันตราย

## `POST /api/danger-zones`

ทีละ 1 เขต ไม่ผูกกับผู้ป่วยคนไหน

### Request

```json
{
  "name": "คลองหลังหมู่บ้าน",
  "center_latitude": 13.7550,
  "center_longitude": 100.5000,
  "radius_meters": 120,
  "zone_type": "waterway",
  "rationale": "เคยมีคนตกเมื่อปีที่แล้ว ไม่มีราวกั้น"
}
```

| ฟิลด์ | ชนิด | บังคับ | ช่องในฟอร์ม |
|---|---|---|---|
| `name` | string | ✅ | ชื่อเขต |
| `center_latitude` / `center_longitude` | float | ✅ | หมุดบนแผนที่ |
| `radius_meters` | float | ✅ | ลากรัศมี |
| `zone_type` | `highway` \| `waterway` \| `construction` \| `other` | ✅ | dropdown ประเภท |
| `rationale` | string | ✅ | "ทำไมที่นี่อันตราย" |
| `created_by` | string | ❌ (default `"admin_ui"`) | ชื่อผู้ดูแลที่เป็นคนตั้ง ถ้ามี |

`rationale` **บังคับกรอกจริงๆ** (คอลัมน์เป็น NOT NULL) — ระบบกฎทั้งหมดออกแบบให้ทุกกฎ
อธิบายที่มาได้ตอนถูกตรวจ ห้ามปล่อยว่างหรือใส่ค่า default ให้

`source_reference` **backend ใส่เอง** เป็น `"caregiver_input"` UI ไม่ต้องส่ง
`created_by` ส่งมาก็ได้ ไม่ส่งก็ได้ — มันไปลงใน audit trail ว่าใครเป็นคนตั้งเขตนี้
ถ้าหน้า admin รู้ชื่อผู้ดูแลอยู่แล้วก็ส่งมา จะตามกลับได้ตอนทบทวนทีหลัง

### Response `201`

```json
{"id": 3, "name": "คลองหลังหมู่บ้าน", "center_latitude": 13.7550,
 "center_longitude": 100.5000, "radius_meters": 120, "zone_type": "waterway",
 "rationale": "เคยมีคนตกเมื่อปีที่แล้ว ไม่มีราวกั้น", "active": true}
```

## `GET /api/danger-zones`

คืน list ของเขตที่ `active = true` ทั้งหมด

## `DELETE /api/danger-zones/{id}`

ไม่ลบจริง — set `active = false` (เก็บประวัติไว้ตามดีไซน์ของ rule KB) คืน `204`

# 3. เคส error

| กรณี | รหัส | detail |
|---|---|---|
| `patient_id` ไม่มีในตาราง `users` | `404` | `patient not found — call /api/register first` |
| lat/lon นอกช่วง | `422` | pydantic บอกฟิลด์ที่ผิด |
| `places` เป็น array ว่าง | `422` | `places must not be empty` |
| `visit_rank`/`stay_rank`/`zone_type` ไม่ตรง enum | `422` | pydantic |
| `rationale` ว่างหรือไม่ส่ง | `422` | `rationale is required` |

# 4. ข้อควรรู้ที่ UI ต้องสื่อกับผู้ดูแล

1. **หมุดต้องปักบนแผนที่ ห้าม geocode จากที่อยู่** — รัศมีจับคู่สถานที่ default แค่ 150 ม.
   ที่อยู่แบบ "หมู่ 4 ต.xxx" geocoder มักตกกลางตำบล ห่างเป็นกิโล ผลคือระบบมองบ้านจริง
   เป็นที่แปลกหน้าแล้วเตือนทั้งวัน — **หมุดผิดแย่กว่าไม่มีหมุด** ช่องที่อยู่มีไว้ช่วยหา
   ตำแหน่งบนแผนที่และให้คนอ่าน ไม่ใช่แหล่งพิกัด
2. **ปัก 3–5 หมุด** — บ้านห้ามขาด น้อยกว่านี้ไม่มีอะไรให้ระบบเทียบ มากเกินไปที่ที่
   นานๆ ไปทีจะถูกนับเป็น "คุ้นเคย"
3. **ที่ใหญ่ๆ ใช้ `radius_m`** ถ้ายังไม่รองรับ ให้ปักหลายหมุดคลุมแทน
4. ควรทำให้ผู้ดูแลปักหมุด **ก่อน** เริ่มเก็บ GPS ไม่ใช่ปักทีหลัง

# 5. อยู่นอกขอบเขตของ contract นี้

- แก้/ลบหมุดทีละอัน — ใช้ POST ทับทั้งชุดแทน
- Auth — ยังไม่มีทั้งระบบ (D5) endpoint พวกนี้ยังเปิดโล่ง **ห้ามแชร์ URL ออกนอกทีม**
- `routine_patterns`, `typical_range_km` — เป็นของ AI Module 1 คนไม่ต้องกรอก
