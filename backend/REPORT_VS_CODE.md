# รายงาน vs โค้ดจริง — ตารางช่องว่าง

> **นี่ไม่ใช่การตรวจงานใคร** เอกสารของโปรเจกต์นี้มีหลายฉบับและเขียนคนละเวลา — รายงาน
> เขียน 5 ก.ค. แผน 4 สัปดาห์ตกลง 14 ส.ค. โค้ดเปลี่ยนเกือบทุกวัน พอฉบับหนึ่งเปลี่ยน อีกฉบับ
> ไม่ได้เปลี่ยนตาม ทุกคนทำถูกตามเอกสารที่ตัวเองถืออยู่ แล้วผลลัพธ์ก็ไม่ตรงกัน
>
> ตัวเร่งที่ชัดที่สุดคือ **โค้ดฝั่งแอปกับฝั่ง backend ไม่ได้อยู่รีโปเดียวกัน** สิ่งที่ฝั่งหนึ่งเขียน
> จึงไม่มีทางไปโผล่ให้อีกฝั่งเห็นเอง ไม่ว่าจะเขียนละเอียดแค่ไหน เอกสารนี้มีไว้เพื่อให้ทั้งสองฝั่ง
> ดูตารางเดียวกันว่า **ตอนนี้ backend ทำอะไรได้จริง** จะได้ไม่ต้องเดา
>
> **วิธีทำ:** ดึงข้อความจาก `docs/PathGuard AI .pdf` ออกมาทั้งฉบับด้วย `pdftotext` แล้วไล่ทุกข้อ
> ที่แตะ backend เทียบกับโค้ดใน `app/` ทีละบรรทัด — **ทุกช่องมีเลขบรรทัดอ้างอิง ไม่มีข้อไหน
> มาจากความจำ** ถ้าช่องไหนผิด แก้ได้เลยพร้อมเลขบรรทัดที่ยืนยัน
>
> **ยังไม่ได้ยืนยันกับฝั่งแอป** — คำถามท้ายไฟล์คือข้อที่ดูจากโค้ดฝั่ง backend อย่างเดียวแล้วตอบไม่ได้

| บรรทัด 261 + 353: **รัศมีค้นหาปรับตามระยะของโรค** | ✅ **สร้างแล้ว 2026-08-26** `adjust_radius(..., severity_level=)` ระยะกลาง −20% ระยะแรก +20% ไม่ระบุระดับ = ไม่ปรับ **ข้อควรรู้: การหด "ไม่ทบกัน"** — การหดจาก wandering ต่ำถูกอธิบายไว้เองว่าเป็นตัวแทนของระยะกลาง ถ้าคูณกันจะได้ 0.64 คือหดพื้นที่ค้นหาผู้ป่วยที่หายไป 36% จากสัญญาณเดียวที่นับซ้ำ ระบบจึงเลือก**การหดที่น้อยที่สุด** ส่วนการขยายยังทบกันตามเดิมเพราะพื้นที่ใหญ่เกินเป็นทางที่ปลอดภัยกว่า |
| บรรทัด 218: ผู้ป่วยแบ่งเป็น Level 1 / Level 2 | ✅ **มีที่เก็บและมีคนอ่านแล้ว 2026-08-26** `users.severity_level` (1/2, ว่างได้) รับผ่าน `POST /api/patients` · **แก้ข้อความเดิม 2026-08-26:** ที่เคยเขียนว่า "ยังไม่มีโค้ดไหนใน `app/ai` อ่านค่านี้" และ "รัศมีตามระยะโรคยังไม่ได้ทำ" **ผิดทั้งคู่** — `ai/module4_search_area/search_radius_adjustment.py:50` รับ `severity_level` และถูกส่งมาจริงที่ `api/search_area.py:155`, `api/recommendation.py:90` (เลือก 3 หรือ 5) และ `api/trip_requests.py:155` (Level 2 เท่านั้นที่ต้องขออนุมัติ) · **เพิ่ม 2026-08-27:** ฝั่ง*แอป*เพิ่งอ่านค่านี้ได้จริง — เดิมค่าออกจาก backend ทางเดียวคือ response ของ `POST /api/patients` ซึ่งเป็นการเรียกของผู้ดูแล เครื่องผู้ป่วยจึงไม่มีทางรู้ระดับของตัวเองเลย ตอนนี้มี `GET /api/patients/{patient_id}` และ `POST /api/pair` คืน `severity_level` มาด้วย |
| Module 1 เรียนรู้สถานที่เอง | สร้างแล้ว วัดแล้ว **ตัดสินใจ 2026-08-26 ว่าไม่ใช้** — DBSCAN บน raw fix ให้ 142–156 "สถานที่" ไม่มีชื่อ และชี้ทีมค้นหาไปที่ centroid ของถนน production ใช้หมุดที่ผู้ดูแลปักแทน **รายงานจะเขียนเรื่องนี้เป็นผลการทดลอง ไม่ใช่ซ่อน** |

## คำถามที่ตอบได้จากฝั่งแอปเท่านั้น

1. **รหัสจับคู่เครื่องผู้ป่วย — backend สร้างให้แล้ว 2026-08-26** (`POST /api/patients` +
   `POST /api/pair`, ดู `API_CONTRACT_APP.md` หัวข้อ 2) ฝั่งแอปต้องเปลี่ยน 2 จุด: หน้าผู้ดูแล
   เรียก `POST /api/patients` แทนการสร้างรหัสเอง และหน้าผู้ป่วยเอา `firebase_custom_token`
   ที่ได้ไปเข้า `signInWithCustomToken()` **รับได้ไหม หรือรหัสฝั่งแอปผูกกับอย่างอื่นไปแล้ว**
2. หน้าผู้ดูแลเก็บ "สถานที่ปลอดภัย" ได้กี่ที่ต่อผู้ป่วยหนึ่งคน — ที่เดียวหรือหลายที่
3. Real-time Navigation / Off-route ตอนนี้ทำถึงไหน ใช้บริการเส้นทางเจ้าไหน หรือยังไม่เริ่ม
4. Caregiver Community (แชท) — แผนตัดไปแล้ว แต่รายงานยังมี ตอนนี้สร้างอยู่หรือเปล่า
5. "แจ้งผู้ดูแลทุกคน + จัดอันดับระยะทาง" — ต้องมีผู้ดูแลหลายคนต่อผู้ป่วย ตอนนี้แอปคิดไว้ว่ากี่คน
