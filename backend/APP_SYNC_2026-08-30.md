## 1. ทำไมฝั่ง backend ทำแทนให้ไม่ได้

คำถามตรงและควรได้คำตอบตรง มี 3 ข้อ เรียงจากที่หนักที่สุด

**ข้อ 1 — เครื่องฝั่ง backend ไม่มี Flutter ติดตั้งอยู่เลย** (`flutter: command not
found`) แปลว่าโค้ด Dart ทุกบรรทัดที่เขียนออกไป **คอมไพล์ไม่ได้ รันไม่ได้ แม้แต่
`flutter analyze` ก็ไม่ได้** ส่งไปก็คือส่งโค้ดที่ไม่เคยผ่านอะไรเลยสักด่าน แล้วคุณต้อง
มานั่งไล่แก้ error ของคนอื่นแทนที่จะเขียนเอง — ช้ากว่าเดิม

**ข้อ 2 — ไฟล์ที่ต้องแก้คือไฟล์ที่คุณกำลังแก้อยู่ทุกวัน** `caregiver_homepage_screen.dart`,
`patient_login_screen.dart`, หน้าจอ homepage ทั้งสอง level มี commit ลงไปวันนี้ทั้งนั้น
ถ้าสองฝั่งแก้พร้อมกันคือ conflict แน่นอน และเป็น conflict ในไฟล์ที่ฝั่งเราตัดสินใจแทน
ไม่ได้ว่าอันไหนถูก

**ข้อ 3 — งานที่เหลือส่วนใหญ่ไม่ใช่ "ต่อ endpoint" แต่เป็นการตัดสินใจเรื่อง UX**
GPS เริ่มส่งตอนไหน · หน้าจอไหนโชว์ error เมื่อ backend ล่ม · ผู้ดูแลกรอกเบอร์ตอนสมัคร
หรือแก้ทีหลัง — ทั้งหมดเป็นของฝั่งคุณตามที่ทีมตกลงกันตั้งแต่วันแรกว่า **แบ่งงานตาม
layer ไม่ใช่ตาม feature**

**ดังนั้นสิ่งที่เราทำให้ได้ และทำมาแล้วในเอกสารนี้คือ** เตรียม backend ให้ไม่มีอะไรขวาง
คุณ แล้วเขียนโค้ดที่พร้อมแปะให้ทุกชิ้นในหัวข้อ 4 — คุณเป็นคนกด compile และเป็นคนตัดสิน
ว่าจะรับหรือแก้

> ⚠️ **โค้ด Dart ทุกบล็อกในเอกสารนี้เขียนโดยไม่ได้คอมไพล์** ถือเป็นร่างที่ผ่านการตรวจ
> สัญญาแล้ว (ชื่อ field, ชนิดข้อมูล, status code ตรงกับ `app/` จริง) แต่ syntax ของ Dart
> ยังไม่เคยถูกเครื่องไหนตรวจ ให้ถือว่าเป็นตัวช่วยร่าง ไม่ใช่ของที่การันตี

## 4. งานที่ต้องทำ เรียงตามลำดับ พร้อมโค้ด

ลำดับนี้บังคับ — ชิ้น 1 ขวางทุกชิ้น และชิ้น 2 ทำให้ชิ้น 5 มีความหมาย

### ชิ้นที่ 1 — ที่เก็บ session (ทำก่อน ทุกชิ้นรออันนี้)

เพิ่ม `shared_preferences: ^2.3.2` ใน `pubspec.yaml` แล้วสร้างไฟล์ใหม่

```dart
// lib/services/session.dart
import 'package:shared_preferences/shared_preferences.dart';

/// Who this phone is paired to. Survives an app restart on purpose: the
/// pairing code is single-use, so a patient_id lost on close cannot be
/// recovered without the caregiver issuing a brand new code.
class Session {
  Session._();
  static final Session instance = Session._();

  int? patientId;
  String? patientName;
  int? severityLevel;

  bool get isPaired => patientId != null;

  Future<void> load() async {
    final prefs = await SharedPreferences.getInstance();
    patientId = prefs.getInt('patient_id');
    patientName = prefs.getString('patient_name');
    severityLevel = prefs.getInt('severity_level');
  }

  Future<void> save({
    required int patientId,
    required String patientName,
    required int severityLevel,
  }) async {
    this.patientId = patientId;
    this.patientName = patientName;
    this.severityLevel = severityLevel;
    final prefs = await SharedPreferences.getInstance();
    await prefs.setInt('patient_id', patientId);
    await prefs.setString('patient_name', patientName);
    await prefs.setInt('severity_level', severityLevel);
  }

  Future<void> clear() async {
    patientId = null;
    patientName = null;
    severityLevel = null;
    final prefs = await SharedPreferences.getInstance();
    await prefs.remove('patient_id');
    await prefs.remove('patient_name');
    await prefs.remove('severity_level');
  }
}
```

ใน `main.dart` เรียก `await Session.instance.load();` ต่อจาก `Firebase.initializeApp()`
และใน `patient_login_screen.dart` ใส่ก่อน `Navigator.push`

```dart
await Session.instance.save(
  patientId: pairData['patient_id'] as int,
  patientName: name,
  severityLevel: severityLevel,
);
```

จากนั้นถ้า `Session.instance.isPaired` เป็นจริงตอนเปิดแอป ให้ข้ามหน้าล็อกอินไปเลย

**สามเรื่องที่ต้องรู้เกี่ยวกับ endpoint นี้**

1. **มันเขียนทับทั้งชุด ไม่ใช่เพิ่มทีละอัน** ส่ง "บ้านอย่างเดียว" ทีหลัง = หมุดอื่นหายหมด
   เงียบๆ พร้อมสถานะ 201 (มี `PUT /api/patients/{id}/places/home` ไว้แก้บ้านอย่างเดียว
   โดยไม่ลบตัวอื่น ใช้อันนั้นถ้าจะมีหน้าแก้ไข)
2. **`visit_rank` / `stay_rank` เป็น enum ไม่ใช่ตัวเลข** — `daily_live` / `most_days` /
   `weekly` / `rare` และ `all_day` / `few_hours` / `about_hour` / `brief` ที่เป็น enum
   เพราะสูตรความคุ้นเคยคือ `freq ÷ max(freq)` **ถ้าทุกที่ rank เท่ากันหมด ค่าจะเป็น 1.0
   ทุกที่ แล้วระบบจะเลิกแจ้งเตือนไปเลย** ค่าที่ใส่ในโค้ดข้างบนเป็นค่าเริ่มต้นที่รักษาความ
   ต่างไว้ ถ้าจะให้ดีที่สุดควรมี dropdown ให้ผู้ดูแลเลือกเอง แต่ค่านี้ใช้ได้
3. `is_home` มีได้แค่อันเดียว ไม่งั้น 422

### ชิ้นที่ 3 — ส่ง GPS ขึ้น backend

**นี่คือชิ้นที่ปลดล็อกทุกอย่าง** ตอนนี้ `geolocator` ถูกใช้แค่วาดหมุดบนหน้า navigation
ไม่มีบรรทัดไหนส่งพิกัดขึ้นมา ตราบใดที่ไม่มีจุดเข้ามา risk score / alert / track /
search-area จะตอบว่างทั้งหมด ต่อ endpoint ไปก็ไม่มีอะไรให้ดู

```dart
// lib/services/gps_reporter.dart
import 'dart:async';
import 'package:geolocator/geolocator.dart';
import 'api_client.dart';
import 'session.dart';

StreamSubscription<Position>? _sub;
DateTime? _lastSent;

/// Foreground only — reports while the app is open. Background tracking with
/// the screen off needs a foreground service and manifest changes; that is a
/// separate piece of work, see the note under this section.
Future<void> startGpsReporting() async {
  if (_sub != null) return;
  if (!Session.instance.isPaired) return;
  if (!await Geolocator.isLocationServiceEnabled()) return;

  var permission = await Geolocator.checkPermission();
  if (permission == LocationPermission.denied) {
    permission = await Geolocator.requestPermission();
  }
  if (permission == LocationPermission.denied ||
      permission == LocationPermission.deniedForever) {
    return;
  }

  _sub = Geolocator.getPositionStream(
    locationSettings: const LocationSettings(
      accuracy: LocationAccuracy.high,
      distanceFilter: 10,
    ),
  ).listen(_send);
}

Future<void> stopGpsReporting() async {
  await _sub?.cancel();
  _sub = null;
}

Future<void> _send(Position p) async {
  final patientId = Session.instance.patientId;
  if (patientId == null) return;

  // The server rescores at most once a minute per patient anyway, so sending
  // faster than this buys nothing and burns battery and data.
  final now = DateTime.now();
  if (_lastSent != null &&
      now.difference(_lastSent!) < const Duration(seconds: 20)) {
    return;
  }
  _lastSent = now;

  // heading is -1 on devices that cannot report it, and the server validates
  // 0 <= direction < 360 — send null instead of getting a 422 on every point.
  final heading = (p.heading >= 0 && p.heading < 360) ? p.heading : null;

  try {
    await apiPost('/api/gps', body: {
      'patient_id': patientId,
      'latitude': p.latitude,
      'longitude': p.longitude,
      'accuracy': p.accuracy,
      'altitude': p.altitude,
      'speed': p.speed,
      'direction': heading,
      'recorded_at': p.timestamp.toUtc().toIso8601String(),
    });
  } catch (_) {
    // Offline or server down. Dropping one point is fine — the next one is 20
    // seconds away. `POST /api/gps/batch` exists if you ever add an outbox.
  }
}
```

เรียก `startGpsReporting()` ใน `initState` ของ homepage ผู้ป่วยทั้งสอง level และเรียก
`stopGpsReporting()` ตอน logout

**เรื่อง background** — W2 ในแผนคือ "ติดตามต่อเนื่อง 1 ชั่วโมงตอนปิดจอ" ซึ่งอันนี้ทำไม่ได้
ต้องมี foreground service + แก้ `AndroidManifest.xml` + จัดการ battery optimization
**ตกลงกันแล้วว่า pilot รอบนี้เอาแบบ foreground ก่อน** เพราะ pilot คือหนึ่งวันที่มีทีมนั่ง
อยู่ด้วย และเราจะรายงาน W2 ตามจริงว่ายังไม่ผ่าน แทนที่จะรีบทำของที่เทสไม่ได้

**หมายเหตุ `recorded_at`** ต้องเป็น UTC ลงท้าย `Z` — `toUtc().toIso8601String()` ให้
ถูกอยู่แล้ว ถ้าส่งเวลาท้องถิ่นไป ตัวตรวจ GPS หายจะเข้าใจผิดว่าเครื่องเงียบไป 7 ชั่วโมง

### ชิ้นที่ 4 — SOS ของจริง

```dart
// lib/services/sos_service.dart
import 'package:geolocator/geolocator.dart';
import 'api_client.dart';
import 'session.dart';

Future<bool> triggerSOS() async {
  final patientId = Session.instance.patientId;
  if (patientId == null) return false;

  // Coordinates are optional on purpose: a patient pressing SOS must not wait
  // for a GPS fix, and the server accepts the alert without one.
  Position? here;
  try {
    here = await Geolocator.getCurrentPosition()
        .timeout(const Duration(seconds: 5));
  } catch (_) {}

  final response = await apiPost('/api/sos', body: {
    'patient_id': patientId,
    if (here != null) 'latitude': here.latitude,
    if (here != null) 'longitude': here.longitude,
  });

  return response.statusCode == 201;
}
```

signature เดิม (`Future<bool>`) ไม่เปลี่ยน จุดที่เรียกทั้ง 6 ที่ไม่ต้องแก้

**สิ่งที่ response ส่งกลับมาและควรใช้** — `alert_id`, `severity` (เป็น `"critical"` เสมอ),
`push` (บอกว่าส่ง push ออกไปสำเร็จไหม — **201 ไม่ได้แปลว่าถึงมือผู้ดูแลแล้ว**) และ
`severity_level` ซึ่งคือระดับของโรค **คนละเรื่องกับ `severity` ที่อยู่ข้างบน** ตัวนี้แหละ
คือตัวที่ report §1.6 ใช้แตกทาง Level 1 ไปที่ปลอดภัยที่ใกล้ที่สุด, Level 2 เข้า Zero-UI
ให้ยืนอยู่กับที่รอคนมารับ **อ่านผิดตัวคือส่งผู้ป่วยระยะกลางออกไปข้ามถนน**

มี cooldown 60 วินาทีต่อผู้ป่วยหนึ่งคน กดรัวไม่สแปมผู้ดูแล

### ชิ้นที่ 5 — Smart Recommendation ของจริง

```dart
final patientId = Session.instance.patientId!;
final response = await apiGet(
  '/api/recommendation/$patientId',
  queryParams: {'lat': currentLat, 'lng': currentLng},  // ทั้งคู่ใส่หรือไม่ใส่ก็ได้
);
final body = jsonDecode(response.body);
final places = body['recommendations'] as List;  // เรียงตาม rank มาแล้ว
```

แต่ละอันมี `rank`, `place_name`, `latitude`, `longitude`, `confidence` (0–1),
`confidence_pct` (0–100) และ `factors`

**สามอย่างที่ต้องรู้**

- **ถ้ายังไม่ทำชิ้นที่ 2 คุณจะได้ `status: "no_profile"` กับ `recommendations: []`**
  นั่นไม่ใช่บั๊ก ไม่มีหมุดก็ไม่มีอะไรให้แนะนำ **ทำชิ้นที่ 2 ก่อนแล้วค่อยต่ออันนี้** ไม่งั้น
  จะเสียเวลาไล่หาบั๊กที่ไม่มีอยู่จริง
- `place_name` เป็น `null` ได้ (สถานที่ที่ระบบเรียนรู้เองตั้งชื่อไม่ได้) — ให้ **ซ่อนไทล์
  นั้น** อย่าโชว์คำว่า "ไม่ทราบ" ในทางปฏิบัติทุกอันมาจากหมุดของผู้ดูแล จึงมีชื่อเสมอ
- คืน **3 อัน ทั้ง Level 1 และ Level 2** ตามที่คุณขอมาเมื่อ 28 ส.ค. มีเทสล็อกไว้แล้ว

### ชิ้นที่ 6 — Trip approval ผ่าน backend ด้วย

ตอนนี้เขียน Firebase ตรงๆ ซึ่งทำงานได้และเทสผ่านแล้ว **ไม่ต้องรื้อ** แค่เพิ่มการเรียกเรา
หนึ่งครั้งก่อนเขียน Firebase

```dart
final response = await apiPost('/api/trip-requests', body: {
  'patient_id': Session.instance.patientId,
  'destination_name': place['name'],
  'latitude': place['lat'],
  'longitude': place['lng'],
});
final trip = jsonDecode(response.body);
// trip['confidence'] 0–1 · trip['status'] pending | approved | rejected | not_required
// แล้วค่อยเขียน trip_requests/{id} ลง Firebase เหมือนเดิม โดยแนบ confidence ไปด้วย
```

**ทำไมถึงคุ้มกับการเพิ่มบรรทัดเดียว** — `confidence` คือ Confidence Score ที่รายงานเขียน
ไว้ว่าเป็นหัวใจของ C-3 ผู้ดูแลควรเห็นเลขนี้ตอนกดอนุมัติ ("ที่นี่ห่างจากที่ที่เขารู้จักแค่
ไหน") ถ้าไม่เรียก ฟีเจอร์นี้จะมีอยู่ในโค้ดแต่ไม่มีใครได้เห็นเลย

Level 1 จะได้ `status: "not_required"` และ `id: null` (ไม่บันทึกแถว) — แต่คุณตัดสินใจ
ให้ Level 1 ต้องขออนุมัติด้วย ถ้าอยากให้ Level 1 บันทึกแถวจริงบอกมา เราปรับให้ได้

### ชิ้นที่ 7 — Firebase Auth + register ฝั่งผู้ดูแล

ลำดับที่ถูก

1. รื้อ `EmailTextField` / `PasswordTextField` ให้รับ `controller` (ดูข้อ 3.3)
2. `FirebaseAuth.instance.signInWithEmailAndPassword(...)` — **ผู้ดูแลใช้ email/password
   ปกติ ไม่ใช่ custom token แบบผู้ป่วย**
3. ถ้าเป็นบัญชีใหม่ ยิง `POST /api/register`

```dart
final user = FirebaseAuth.instance.currentUser!;
await apiPost('/api/register', body: {
  'firebase_uid': user.uid,
  'name': nameController.text,
  'role': 'caregiver',
  'phone': phoneController.text,   // ← เพิ่มช่องนี้ในฟอร์มด้วย
});
```

4. เอา `caregiver_id: 12` ออก แล้วใช้ `id` ที่ `/api/register` คืนมา (หรือเลขที่เราส่งให้
   ในแชทสำหรับบัญชีทดสอบ)

**บัญชีทดสอบที่เราสร้างให้แล้ว** — `caregiver1@gmail.test` รหัสผ่านและ `caregiver_id`
อยู่ในแชท **ไม่ใส่ในไฟล์นี้เพราะ repo เป็น public** เป็นบัญชีจริงใน Firebase project
`pathguard-ai-2d047` ล็อกอินได้เลย

⚠️ **`POST /api/register` ไม่เปิดเมื่อ `AUTH_ENABLED=true`** ต้อง sign in Firebase ให้
เสร็จก่อนแล้วส่ง `Authorization: Bearer <ID token>` มาด้วย ไม่งั้น 401 — ซึ่งตรงกับลำดับ
ข้างบนอยู่แล้ว แต่บอกไว้เผื่อสลับลำดับ

### ชิ้นที่ 8 — Safe Zone Navigation (ของฝั่งคุณล้วน ไม่ต้องรอเรา)

คุณเขียนว่ารอเราทำ data model **คำตอบคือไม่ต้องรอ ทำเองได้เลยและเร็วกว่า**

ใช้ **Places API (New) → Nearby Search** ที่คุณเปิดใช้ไปแล้ววันนี้

```
POST https://places.googleapis.com/v1/places:searchNearby
{
  "includedTypes": ["police", "hospital"],
  "maxResultCount": 5,
  "locationRestriction": {
    "circle": {"center": {"latitude": lat, "longitude": lng}, "radius": 3000.0}
  }
}
```

ได้พิกัดมาแล้วโยนเข้า `directions_service.dart` ที่ทำเสร็จแล้ว ไม่ต้องเขียนส่วนนำทางใหม่
ตัวแตกทาง Level 1 / Level 2 อ่านจาก `severity_level` ที่ `POST /api/sos` คืนมา (ชิ้นที่ 4)

**ทำไมไม่ทำเป็นตารางฝั่ง backend** — เราจะต้องนั่งกรอกโรงพัก/โรงพยาบาลเองทีละแห่ง แล้ว
มันจะเก่าและผิดโดยไม่มีใครรู้ ส่วน Google มีข้อมูลนี้อยู่แล้วและอัปเดตให้ ในเมื่อ key
อยู่ในมือคุณและ Directions ก็เขียนเสร็จแล้ว ทางนี้เร็วกว่ามาก

**ข้อควรระวังเรื่องเงิน** — Nearby Search เป็นคนละ SKU กับ Autocomplete **session token
ไม่ครอบ** กด SOS หนึ่งครั้ง = หนึ่ง call ที่คิดเงิน ปริมาณน้อยมากจึงไม่มีปัญหา แต่อย่าไป
เรียกซ้ำใน loop

**ข้อจำกัดที่ยอมรับ** — backend จะไม่รู้ว่าผู้ป่วยถูกพาไปไหน วัน pilot ที่มีทีมอยู่ด้วย
ยอมรับได้ ถ้าอยากให้รู้ทีหลังค่อยคุยกัน

## 6. เรื่อง `AUTH_ENABLED` — อ่านก่อนวันเทสรวม

ตอนนี้ยังปิดอยู่ ทุกอย่างจึงเรียกได้โดยไม่ต้องมี token **แต่แผนคือวันจริงต้องเปิด** และ
วินาทีที่เปิด

- ฝั่งผู้ป่วยรอด เพราะ `signInWithCustomToken` ทำงานแล้ว มี token จริง
- **ฝั่งผู้ดูแลตายทันที** `currentUser` เป็น `null` → ส่ง `Bearer ` ว่าง → 403 ทุกเส้น
  รวมถึงปุ่ม Add Patient ที่ตอนนี้ใช้งานได้
- และ `caregiver_id` ใน body จะถูก **เมินทิ้ง** — เมื่อ auth เปิด ระบบใช้ id ของเจ้าของ
  token แทนเสมอ (ป้องกันไม่ให้ใครก็ตามที่ล็อกอินได้ผูกผู้ป่วยเข้ากับบัญชีคนอื่น แล้วดู
  ตำแหน่งสดของผู้ป่วยคนนั้นไปตลอด)

**แปลว่าชิ้นที่ 7 คือเงื่อนไขของการเปิด auth** เราจะไม่เปิดจนกว่าคุณจะบอกว่าพร้อม

## 7. เทสรวมได้เลยตั้งแต่ตอนนี้ ไม่ต้องรอครบ 8 ชิ้น

ของที่คุณมีวันนี้ — สร้างผู้ป่วย → ได้รหัส → เครื่องผู้ป่วยจับคู่ — **เทสข้ามเครื่องจริง
ได้แล้ว** เราเปิด tunnel ชี้มาที่เครื่องเราแล้วส่ง URL ให้คุณใส่ใน `.env`
(`BACKEND_BASE_URL`) ใช้เวลาไม่กี่นาที

คุ้มมาก เพราะ **สาย pairing ทั้งเส้นยังไม่เคยถูกรันจริงจากอะไรเลย** ทั้งฝั่งเราและฝั่งคุณ
ถ้ามีอะไรผิด เจอวันนี้ดีกว่าเจอวันที่นั่งอยู่บ้านผู้ป่วย

บอกเวลาที่สะดวกมา — URL ของ `trycloudflare.com` เปลี่ยนทุกครั้งที่เปิดใหม่ เลยต้องนัดกัน
